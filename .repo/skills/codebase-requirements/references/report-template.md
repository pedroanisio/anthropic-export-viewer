| Prefix | Section | Example |
|---|---|---|
| FR- | Functional Requirements (§4) | FR-001 |
| NFR- | Non-Functional Requirements (§5) | NFR-001 |
| DM- | Data Models (§6) | DM-001 |
| API- | API Contracts (§7) | API-001 |

| TST- | Tests (§9) | TST-001 |
| DEP- | Dependencies (§10) | DEP-001 |
| GAP- | Gaps and Risks (§12) | GAP-001 |

When one item references another, use the format: "See FR-003, DM-002"
or "Cross-references: FR-001, API-005, DM-001".

## Table formatting rules

- All tables must use proper Markdown pipe syntax with header separators.
- Align columns for readability when practical, but do not pad excessively.
- Use backtick code formatting for file paths, variable names, and code.
- Use "—" (em dash) for empty/not-applicable cells, not blank cells.
- Keep cell content concise — move detailed explanations to subsections.
