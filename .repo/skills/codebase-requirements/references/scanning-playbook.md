# Scanning Playbook

Concrete detection heuristics for each section of the REQUIREMENTS.md report.
Organized by report section. Each subsection provides file patterns, grep
commands, and ecosystem-specific signals.

Use these as a starting checklist — not every pattern applies to every repo.
Skip what's irrelevant, and add repo-specific patterns as you discover them
during orientation.

## 1. Provenance Detection

### Authors and contributors

```bash
# Git metadata (if .git exists)
git log --format='%aN <%aE>' | sort -u
git log --format='%cN <%cE>' | sort -u
git shortlog -sn --all

# Config files
grep -ri 'author' package.json pyproject.toml Cargo.toml pom.xml *.gemspec setup.py setup.cfg 2>/dev/null
grep -ri 'maintainer' package.json pyproject.toml 2>/dev/null

# License headers in source files
head -5 $(find . -name '*.ts' -o -name '*.py' -o -name '*.go' -o -name '*.java' -o -name '*.rs' | head -20) 2>/dev/null
```

### Repository origin

```bash
git remote -v 2>/dev/null
cat .git/config 2>/dev/null | grep -A2 '\[remote'
grep -i 'repository\|homepage\|bugs' package.json 2>/dev/null
```

### License

```bash
find . -maxdepth 2 -iname 'license*' -o -iname 'licence*' -o -iname 'copying*'
grep -i 'license\|licence' package.json pyproject.toml Cargo.toml 2>/dev/null
# SPDX identifiers in file headers
grep -r 'SPDX-License-Identifier' --include='*.ts' --include='*.py' --include='*.go' --include='*.rs' -l 2>/dev/null
```

### Version history

```bash
find . -maxdepth 2 -iname 'changelog*' -o -iname 'changes*' -o -iname 'history*' -o -iname 'release*'
grep '"version"' package.json 2>/dev/null
grep 'version' pyproject.toml Cargo.toml 2>/dev/null
git tag --list 2>/dev/null | tail -20
git log --oneline -20 2>/dev/null
```

### Boilerplate / template origin

```bash
# Common generator markers
find . -maxdepth 3 -name '.yo-rc.json' -o -name '.cruft.json' -o -name 'cookiecutter.json' -o -name '.hygen.js'
grep -ri 'generated by\|bootstrapped with\|created with\|scaffolded' README* 2>/dev/null
grep -ri 'create-react-app\|create-next-app\|vue-cli\|angular-cli\|rails new\|django-admin startproject\|cargo init\|go mod init' . --include='README*' --include='package.json' 2>/dev/null
```

## 2. Asset Inventory Scanning

### File tree generation

```bash
# Quick annotated tree (if scan_tree.sh is available)
bash scripts/scan_tree.sh /path/to/repo

# Manual fallback
find . -not -path '*/node_modules/*' -not -path '*/.git/*' -not -path '*/vendor/*' \
       -not -path '*/__pycache__/*' -not -path '*/dist/*' -not -path '*/build/*' \
       -type f | sort

# File type distribution
find . -not -path '*/node_modules/*' -not -path '*/.git/*' -type f | \
  sed 's/.*\.//' | sort | uniq -c | sort -rn | head -30

# Largest files (potential binaries or generated code)
find . -not -path '*/node_modules/*' -not -path '*/.git/*' -type f \
  -exec ls -la {} \; | sort -k5 -rn | head -20
```

### Classification signals

Use the taxonomy in `references/asset-taxonomy.md` for the full classification
scheme. Quick detection patterns:

- **Entry points**: `main.ts`, `index.ts`, `app.ts`, `server.ts`, `main.py`,
  `app.py`, `manage.py`, `main.go`, `cmd/`, `bin/`, `src/main.rs`
- **Route definitions**: files containing `router`, `routes`, `controller`,
  `handler`, `endpoint`, `api/` directories
- **Models/schemas**: files containing `model`, `schema`, `entity`, `migration`,
  `prisma/schema.prisma`, `models/`, `entities/`
- **Config**: `.*rc`, `*.config.*`, `*.conf`, `.env*`, `config/`, `settings.*`
- **Tests**: `*test*`, `*spec*`, `__tests__/`, `test/`, `tests/`, `spec/`
- **Docs**: `*.md`, `docs/`, `wiki/`, `*.rst`, `*.adoc`
- **CI/CD**: `.github/workflows/`, `.gitlab-ci.yml`, `Jenkinsfile`, `.circleci/`,
  `bitbucket-pipelines.yml`, `.travis.yml`
- **Build artifacts / generated**: `dist/`, `build/`, `out/`, `.next/`,
  `coverage/`, `*.generated.*`, `*.g.dart`, files with "DO NOT EDIT" headers

## 3. Functional Requirements Extraction

Functional requirements are extracted from behavioral code, not utility code.
Look for the boundary between "what the system does for users" and "how it
does it internally."

### Route and handler discovery

```bash
# Express / Koa / Fastify / Hono (Node.js)
grep -rn 'app\.\(get\|post\|put\|patch\|delete\|use\)\|router\.\(get\|post\|put\|patch\|delete\)' --include='*.ts' --include='*.js' 2>/dev/null

# Next.js / Remix / SvelteKit (file-based routing)
find . -path '*/app/*' -name 'route.ts' -o -name 'page.tsx' -o -name '+page.svelte' -o -name '+server.ts' 2>/dev/null
find . -path '*/pages/api/*' -name '*.ts' -o -name '*.js' 2>/dev/null

# Django
grep -rn 'urlpatterns\|path(\|re_path(' --include='*.py' 2>/dev/null
grep -rn 'class.*View\|class.*ViewSet\|class.*APIView' --include='*.py' 2>/dev/null

# Flask / FastAPI
grep -rn '@app\.\(route\|get\|post\|put\|delete\)\|@router\.' --include='*.py' 2>/dev/null

# Rails
grep -rn 'resources\|get\|post\|put\|patch\|delete\|root' config/routes.rb 2>/dev/null

# Go (net/http, gin, echo, chi, fiber)
grep -rn 'HandleFunc\|Handle\|GET\|POST\|PUT\|DELETE\|r\.Route\|e\.GET\|app\.Get' --include='*.go' 2>/dev/null

# Spring (Java/Kotlin)
grep -rn '@GetMapping\|@PostMapping\|@PutMapping\|@DeleteMapping\|@RequestMapping' --include='*.java' --include='*.kt' 2>/dev/null
```

### CLI command discovery

```bash
grep -rn 'commander\|yargs\|argparse\|clap\|cobra\|click\|typer\|oclif\|clipanion' --include='*.ts' --include='*.py' --include='*.go' --include='*.rs' -l 2>/dev/null
grep -rn '\.command(\|\.option(\|add_argument\|#\[arg\|#\[command\]' --include='*.ts' --include='*.py' --include='*.rs' 2>/dev/null
```

### Event and queue consumers

```bash
grep -rn 'on(\|addEventListener\|subscribe\|consume\|process\|@EventPattern\|@MessagePattern\|celery.*task\|@task\|@shared_task\|Bull\|BullMQ\|SQS\|RabbitMQ\|Kafka' --include='*.ts' --include='*.py' --include='*.go' -l 2>/dev/null
```

### Scheduled / cron jobs

```bash
grep -rn 'cron\|schedule\|setInterval\|@Cron\|periodic_task\|crontab' --include='*.ts' --include='*.py' --include='*.go' --include='*.yaml' --include='*.yml' 2>/dev/null
find . -name 'crontab*' -o -name '*cron*' -o -name '*scheduler*' 2>/dev/null
```

### UI components (for frontend-inclusive codebases)

```bash
# React / Vue / Svelte / Angular component files
find . -name '*.tsx' -o -name '*.jsx' -o -name '*.vue' -o -name '*.svelte' -o -name '*.component.ts' 2>/dev/null | head -50
# Page-level components (higher-level features)
find . -path '*/pages/*' -o -path '*/views/*' -o -path '*/screens/*' 2>/dev/null
# State management
grep -rn 'createStore\|configureStore\|createSlice\|useReducer\|createContext\|defineStore\|createSignal\|writable\|atom(' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.jsx' --include='*.vue' --include='*.svelte' -l 2>/dev/null
```

### Requirement assignment

For each behavioral unit discovered above, produce a functional requirement
with: unique ID (FR-001, FR-002, ...), description, associated source files,
inputs/outputs/side effects, and user roles if discernible from auth guards
or permission checks.

## 4. Non-Functional Requirements Detection

### Performance

```bash
# Caching
grep -rn 'cache\|redis\|memcached\|lru_cache\|@cache\|stale-while-revalidate\|Cache-Control\|ETag\|If-None-Match' --include='*.ts' --include='*.py' --include='*.go' --include='*.java' -l 2>/dev/null

# Pagination
grep -rn 'paginate\|page_size\|limit\|offset\|cursor\|skip\|take\|per_page\|pageSize' --include='*.ts' --include='*.py' --include='*.go' 2>/dev/null

# Rate limiting
grep -rn 'rateLimit\|rate_limit\|throttle\|RateLimiter\|express-rate-limit\|slowapi\|token.bucket\|leaky.bucket' --include='*.ts' --include='*.py' --include='*.go' -l 2>/dev/null

# Lazy loading
grep -rn 'lazy\|React\.lazy\|dynamic import\|import(\|loadable\|code.split' --include='*.ts' --include='*.tsx' --include='*.js' 2>/dev/null
```

### Security

```bash
# Authentication
grep -rn 'passport\|jwt\|jsonwebtoken\|bcrypt\|argon2\|oauth\|auth0\|firebase.auth\|clerk\|next-auth\|lucia\|session\|cookie.*sign' --include='*.ts' --include='*.py' --include='*.go' -l 2>/dev/null

# Authorization / RBAC
grep -rn 'authorize\|permission\|role\|guard\|policy\|can(\|ability\|@Roles\|@Permissions\|has_permission\|IsAuthenticated\|IsAdminUser' --include='*.ts' --include='*.py' --include='*.go' 2>/dev/null

# Input validation
grep -rn 'zod\|yup\|joi\|class-validator\|ajv\|Pydantic\|marshmallow\|cerberus\|validator\|sanitize\|escape\|DOMPurify' --include='*.ts' --include='*.py' -l 2>/dev/null

# CORS / CSRF / CSP
grep -rn 'cors\|csrf\|csp\|helmet\|Content-Security-Policy\|X-Frame-Options\|Strict-Transport-Security' --include='*.ts' --include='*.py' --include='*.go' --include='*.yaml' 2>/dev/null

# Encryption
grep -rn 'crypto\|encrypt\|decrypt\|AES\|RSA\|SSL\|TLS\|https\|certificate' --include='*.ts' --include='*.py' --include='*.go' -l 2>/dev/null
```

### Logging and monitoring

```bash
grep -rn 'winston\|pino\|bunyan\|morgan\|log4j\|logback\|slog\|zerolog\|tracing\|logging\.\|logger\.\|console\.log\|console\.error\|Sentry\|Datadog\|NewRelic\|prometheus\|opentelemetry\|honeycomb' --include='*.ts' --include='*.py' --include='*.go' --include='*.java' -l 2>/dev/null
```

### Error handling

```bash
grep -rn 'catch\|except\|rescue\|recover\|ErrorBoundary\|error.handler\|middleware.*error\|@ExceptionHandler\|fallback' --include='*.ts' --include='*.py' --include='*.go' --include='*.java' 2>/dev/null | head -30
```

### Accessibility and i18n

```bash
# a11y
grep -rn 'aria-\|role=\|tabIndex\|alt=\|sr-only\|screen-reader\|a11y\|axe\|lighthouse' --include='*.tsx' --include='*.jsx' --include='*.html' --include='*.vue' 2>/dev/null | head -20

# i18n / l10n
grep -rn 'i18n\|intl\|t(\|useTranslation\|gettext\|ngettext\|locale\|ICU\|formatMessage' --include='*.ts' --include='*.tsx' --include='*.py' --include='*.go' -l 2>/dev/null
find . -path '*/locales/*' -o -path '*/translations/*' -o -path '*/i18n/*' -o -name '*.po' -o -name '*.pot' 2>/dev/null
```

## 5. Data Model Discovery

### ORM model files

```bash
# Prisma
find . -name 'schema.prisma' 2>/dev/null

# TypeORM / MikroORM / Sequelize / Drizzle
grep -rn '@Entity\|@Column\|@PrimaryGeneratedColumn\|DataTypes\.\|defineModel\|pgTable\|sqliteTable\|mysqlTable' --include='*.ts' --include='*.js' -l 2>/dev/null

# Django
grep -rn 'class.*models\.Model\|class.*Model.*:' --include='*.py' | grep -v test 2>/dev/null

# SQLAlchemy / Alembic
grep -rn 'class.*Base\|Column(\|relationship(\|declarative_base\|mapped_column' --include='*.py' -l 2>/dev/null

# ActiveRecord (Rails)
find . -path '*/models/*.rb' 2>/dev/null
grep -rn 'has_many\|belongs_to\|has_one\|has_and_belongs_to_many' --include='*.rb' 2>/dev/null

# Go (GORM, ent, sqlc)
grep -rn 'gorm\.Model\|ent\.Schema\|type.*struct.*`db:' --include='*.go' -l 2>/dev/null
```

### Migration files

```bash
find . -path '*/migrations/*' -o -path '*/migrate/*' -o -path '*/db/migrate/*' -o -path '*/alembic/versions/*' -o -name '*.sql' | grep -i migrat 2>/dev/null
find . -name 'knexfile*' -o -name 'ormconfig*' -o -name 'alembic.ini' -o -name 'flyway*' 2>/dev/null
```

### Seed data and fixtures

```bash
find . -path '*/seeds/*' -o -path '*/fixtures/*' -o -path '*/seeders/*' -o -name '*seed*' -o -name '*fixture*' 2>/dev/null | grep -v node_modules | grep -v __pycache__
```

### Storage mechanisms

```bash
# Database connection strings / drivers
grep -rn 'DATABASE_URL\|postgres\|mysql\|sqlite\|mongodb\|redis\|dynamodb\|firestore\|supabase\|planetscale\|turso\|neon\|cockroach' --include='*.ts' --include='*.py' --include='*.go' --include='*.env*' --include='*.yaml' 2>/dev/null

grep -rn 'S3\|GCS\|Azure.*Blob\|multer\|formidable\|busboy\|upload\|storage\.bucket' --include='*.ts' --include='*.py' --include='*.go' -l 2>/dev/null
```

## 9. Dependency Analysis

### Manifest files

```bash
find . -maxdepth 3 \
  -name 'package.json' -o -name 'yarn.lock' -o -name 'pnpm-lock.yaml' \
  -o -name 'package-lock.json' -o -name 'bun.lockb' \
  -o -name 'requirements.txt' -o -name 'Pipfile' -o -name 'poetry.lock' \
  -o -name 'pyproject.toml' -o -name 'setup.py' -o -name 'setup.cfg' \
  -o -name 'Gemfile' -o -name 'Gemfile.lock' \
  -o -name 'go.mod' -o -name 'go.sum' \
  -o -name 'Cargo.toml' -o -name 'Cargo.lock' \
  -o -name 'pom.xml' -o -name 'build.gradle*' \
  -o -name 'composer.json' -o -name 'composer.lock' \
  -o -name 'mix.exs' -o -name 'pubspec.yaml' \
  2>/dev/null | grep -v node_modules
```

### Categorization

For Node.js projects, `package.json` separates `dependencies`,
`devDependencies`, `peerDependencies`, and `optionalDependencies`.
For Python, look at `[project.dependencies]` vs
`[project.optional-dependencies]` in pyproject.toml, or
`requirements.txt` vs `requirements-dev.txt`.

### Staleness signals

```bash
# Lock file age vs manifest age (if git is available)
git log -1 --format='%ai' -- package-lock.json yarn.lock pnpm-lock.yaml 2>/dev/null
git log -1 --format='%ai' -- package.json 2>/dev/null

# Check for known deprecated packages (Node.js)
# If npm is available:
# npm outdated 2>/dev/null
# If pip is available:
# pip list --outdated 2>/dev/null
```

## 11. Gap and Risk Detection

### Hardcoded secrets

```bash
# Common patterns (high false-positive rate — verify manually)
grep -rn 'password\s*=\s*["\x27]\|api_key\s*=\s*["\x27]\|secret\s*=\s*["\x27]\|token\s*=\s*["\x27]' \
  --include='*.ts' --include='*.py' --include='*.go' --include='*.java' --include='*.env' \
  2>/dev/null | grep -v test | grep -v example | grep -v node_modules | head -20

# AWS keys
grep -rn 'AKIA[0-9A-Z]\{16\}' . 2>/dev/null
# Private keys
find . -name '*.pem' -o -name '*.key' -o -name '*.p12' -o -name '*.pfx' 2>/dev/null | grep -v node_modules
```

### Dead code signals

```bash
# Exported but never imported (TypeScript/JavaScript — approximate)
grep -rn 'export ' --include='*.ts' --include='*.tsx' -l 2>/dev/null > /tmp/exporters.txt
# Then for each export, check if it's imported anywhere else

# Unreferenced files (approximate — check if any file imports them)
# This requires per-project analysis; no universal one-liner

# TODO / FIXME / HACK markers
grep -rn 'TODO\|FIXME\|HACK\|XXX\|DEPRECATED\|TEMP\|WORKAROUND' \
  --include='*.ts' --include='*.py' --include='*.go' --include='*.java' --include='*.rs' \
  2>/dev/null | grep -v node_modules | head -30
```

### Missing documentation

```bash
# Modules without README
find . -type d -maxdepth 3 -not -path '*/node_modules/*' -not -path '*/.git/*' | while read dir; do
  [ -n "$(ls "$dir"/*.ts "$dir"/*.py "$dir"/*.go 2>/dev/null)" ] && \
  [ ! -f "$dir/README.md" ] && [ ! -f "$dir/README" ] && echo "No README: $dir"
done 2>/dev/null | head -20
```
