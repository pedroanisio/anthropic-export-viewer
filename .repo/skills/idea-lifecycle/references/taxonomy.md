# Idea Lifecycle Taxonomy

This document defines the classification primitives used throughout
the skill. Load it before performing any classification, triage,
portfolio operation, document extraction, or graph operation.

---

## 1. Item Types

Every entry in the portfolio is exactly one of these types.
Type reflects *what the item is*, not how mature it is.

| Type | Definition | Typical Form on Arrival |
|---|---|---|
| **spark** | A raw association, question, or impulse. No structure yet. | "What if X...", a sentence fragment, a screenshot, a link with no annotation |
| **insight** | A realized connection between existing knowledge. Has explanatory power but no actionable direction. | "I just realized that X implies Y", a reframing of a known problem |
| **concept** | A structured idea with at least a problem statement and a tentative approach. Not yet scoped for execution. | A paragraph or two describing what and roughly why |
| **project** | A concept that has been scoped: it has a goal, rough boundaries, and at least one concrete next action. | A brief, a spec draft, a repo with a README |
| **reference** | External material (paper, article, tool, dataset) captured because it is relevant to one or more other items. | A URL, a PDF, a citation, a note about why it matters |

### Type Promotion Path

```
spark → insight (if explanatory power emerges)
spark → concept (if problem + approach crystallize)
insight → concept (if an actionable direction is identified)
concept → project (if scoped with boundaries + next action)
```

Promotion is not automatic. It requires an explicit triage decision.
Items can also move *backward* (a project that lost its scope returns
to concept) or *sideways* (a concept splits into two sparks and an
insight).

---

## 2. Maturity Stages

Maturity is orthogonal to type — it captures *how developed* the item
is within its type.

| Stage | Criteria |
|---|---|
| **raw** | Just captured. No processing, no validation, no linking. |
| **processed** | Reviewed at least once. Core claim is stated clearly. Tagged and linked to related items. |
| **validated** | Core premise tested against reality — even minimally. |
| **active** | Currently receiving attention and effort. Limited: 1–3 projects, 2–5 concepts. |
| **parked** | Deliberately paused. Has a reactivation trigger. |
| **dead** | Killed with a reason. Archived, not deleted. |

## 3. Relationship Types

| Relationship | Notation | Meaning |
|---|---|---|
| **supports** | A → supports → B | A provides evidence, tooling, or framing that strengthens B |
| **contradicts** | A → contradicts → B | A and B cannot both be true or both succeed |
| **subsumes** | A → subsumes → B | A contains B as a special case or subproblem |
| **depends-on** | A → depends-on → B | A cannot proceed unless B is resolved first |
| **inspired-by** | A → inspired-by → B | A originated from B but is now independent |
| **merges-with** | A ↔ merges-with ↔ B | A and B are converging and should be combined |
| **echoes** | A → echoes → B | A re-expresses the same underlying theme as B in a different context (recurrence signal) |
| **tensions-with** | A → tensions-with → B | Not contradictory but productive friction — unresolved tension that may generate new insights |
| **extracted-from** | A → extracted-from → B | A was derived from document/reference B during extraction (provenance chain) |

### Cluster Detection

When three or more items share two or more relationships, they form a
**cluster**. Clusters often indicate an emergent theme that deserves
its own concept-level entry.

---

## 4. Provenance

Every item tracks where it came from. Provenance is critical for
document-fed portfolios — without it, you cannot trace back to
source material, verify claims, or detect when the same document
produced duplicate items.

### Source Types

| Source Type | Description | Key Fields |
|---|---|---|
| **manual** | User typed it directly | `session_id` |
| **document** | Extracted from an uploaded document | `document_id`, `page_or_section`, `extraction_method` |
| **web** | Extracted from a fetched URL | `url`, `fetch_date` |
| **derived** | Generated by Claude during analysis (e.g., an insight surfaced from cross-referencing items) | `derivation_method`, `source_item_ids` |
| **merged** | Created by merging two or more existing items | `source_item_ids` |

### Document Registry

When a document is processed, it gets registered before any items
are extracted. This prevents re-processing and enables provenance.

```json
{
  "document_id": "<ULID>",
  "filename": "<original filename>",
  "type": "pdf | md | txt | docx | html | csv | image",
  "processed_date": "<ISO 8601>",
  "pages_or_sections": "<count or list>",
  "items_extracted": ["<item ids>"],
  "content_hash": "<SHA-256 for dedup detection>"
}
```

## 5. Pattern Types

Patterns are meta-observations — structural properties of the item
network. They are detected during the **diagnose** operation.

| Pattern | Definition | Signal | Action |
|---|---|---|---|
| **recurrence** | Same theme appears across 3+ independently-created items. | Multiple `echoes` relationships converging. | Promote to named concept. This is a core preoccupation. |
| **duplication** | Two+ items express the same idea with surface variation only. | Near-identical `core_statement` values. | Merge. Keep the stronger formulation. |
| **convergence** | Items from different domains trending toward the same problem frame. | Multiple `supports` pointing at same target; cross-cluster shared tags. | Consolidate into a higher-order concept. |
| **divergence** | A single item is fragmenting in incompatible directions. | Multiple `contradicts` or `tensions-with` emanating from one item. | Split the item, or explicitly resolve the contradictions. |
| **dependency-chain** | Linear sequence of 3+ `depends-on` relationships. | Critical path in the graph. | Identify the bottleneck (earliest unresolved item). Focus there. |
| **orphan-cluster** | A group of items with no connections to the rest of the portfolio. | Disconnected subgraph. | Find missing connections or flag for pruning. |
| **gravity-well** | One item has disproportionately many inbound relationships. | In-degree > 2× portfolio average. | May be an under-articulated mega-concept. Decompose it. |
| **staleness-wave** | All items in a cluster untouched for 3+ sessions. | Cluster-wide stale `last_touched`. | Triage the cluster as a unit. Theme may be dead. |

## 6. Priority Signals

| Signal | Question | Scale |
|---|---|---|
| **urgency** | Deadline or decaying opportunity? | none / low / high / critical |
| **energy-match** | Aligns with current cognitive state? | draining / neutral / energizing |
| **leverage** | How many items does this unblock? | 0 / 1–2 / 3+ |
| **novelty-decay** | Losing freshness? | stable / slow-decay / fast-decay |
| **feasibility** | Can next action be taken now? | blocked / constrained / clear |
| **conviction** | Gut-level belief this matters? | low / medium / high |

Priority is context-dependent and re-evaluated each triage session.

---

## 7. Kill Criteria

1. **Redundancy** — Another item covers the same ground better.
2. **Premise collapse** — Core assumption falsified.
3. **Chronic parking** — Parked 3+ cycles, no trigger fired.
4. **Energy black hole** — Consistently draining across sessions.
5. **Orphan** — Zero relationships, user can't articulate why it matters.

## 8. Graph Operations

The portfolio graph evolves through discrete, logged operations.

### Patch

An atomic set of changes applied in a single session:

- **node-add** / **node-update** / **node-kill**
- **edge-add** / **edge-remove** / **edge-retype**
- **cluster-detect** / **cluster-promote**
- **merge** / **split**

Every patch is recorded with a timestamp, summary, and operation list.

### Graph Merge

When two portfolio state files are combined:

1. Union items by ID (most recent `last_touched` wins conflicts).
2. Union relationships. Dedup by `(source_id, target_id, type)`.
3. Re-run cluster detection on merged graph.
4. Flag cross-graph duplications for user resolution.
5. Record as a patch with type `graph-merge`.

### Graph Diff

Compare two graph states:
- Items added / removed / modified
- Relationships added / removed / retyped
- Clusters formed / dissolved
- Patterns emerged / disappeared
